# Roamly Frontend

> Polished, responsive React 19 single-page application (SPA) for the **Roamly** travel discovery and collaborative trip-planning platform. Built with Vite, React Router 7, Lucide Icons, and a bespoke Editorial Vanilla CSS design system.

---

## 1. Overview & Architecture

The Roamly frontend delivers an editorial, high-touch travel journaling and discovery experience. It connects modern travelers with curated global destinations, day-by-day community itineraries, travel budget calculations, and real interactive engagements (wishlist bookmarks, itinerary likes, and discussion comments).

### Key Architectural Characteristics
- **Component-Driven React 19 SPA**: Fast rendering, declarative components, and modular state management with standard React hooks (`useState`, `useEffect`, `useCallback`, `useMemo`).
- **Client-Side Routing with React Router 7**: Seamless browser history management with parameterized routes (`/destinations/:id`, `/trips/:id`, `/trips/:id/edit`), search parameter parsing (`useSearchParams`), and programmatic navigation (`useNavigate`).
- **No Third-Party CSS Frameworks**: Built entirely with hand-crafted Vanilla CSS and centralized CSS custom properties (design tokens). Zero Tailwind, Bootstrap, or component UI library dependencies.
- **Vite Dev Server with Reverse Proxy**: Fast hot module replacement (HMR) during development. The Vite development server automatically proxies all `/api/*` network requests to the backend Express server running on port `5000`.
- **Global Toast Notification Context**: Lightweight React Context (`ToastContext`) providing accessible, non-blocking toast alerts for user interactions (saving bookmarks, liking itineraries, posting comments, and error notifications).

## 3. Pages & Routes

The client router is configured in `src/App.jsx` using React Router 7 (`react-router-dom` v7.18.4):

| Route Path | Page Component | Description & Key Capabilities |
| :--- | :--- | :--- |
| `/` | `HomePage` | Editorial landing page featuring the Roamly manifesto, quick destination search bar, continent spotlight carousel, trending community itineraries, and key value propositions. |
| `/destinations` | `DestinationsPage` | Full curated travel catalog with live text search (title, country, tags), Continent filter pills (All, Europe, Asia, Americas, Africa, Oceania), and Budget Tier filters (`$`, `$$`, `$$$`). |
| `/destinations/:id` | `DestinationDetailPage` | Immersive destination guide displaying hero imagery, optimal travel season, budget tier, narrative overview, wishlist bookmark toggle, and itineraries passing through this destination. |
| `/trips` | `TripsPage` | Community itinerary catalog with keyword search across trip titles and notes, quick destination tags, like counters, and navigation to the trip editor. |
| `/trips/new` | `CreateEditTripPage` | Comprehensive trip builder: destination selector, trip title, date range picker with validation, currency and budget inputs, notes, cover image URL, and dynamic day-by-day stops editor (place, category, cost, notes). Real-time stop count and cost summation. |
| `/trips/:id` | `TripDetailPage` | Full itinerary view featuring author attribution, travel dates, budget metrics, chronological day-by-day stops breakdown with category badges, interactive trip like button, author-only Edit/Delete controls, and a live comment feed with author-only comment deletion. |
| `/trips/:id/edit` | `CreateEditTripPage` | Pre-populated editor for existing itineraries. Validates author ownership upon submission, allows editing all trip metadata, and synchronizes stop additions, edits, and removals. |
| `/profile` | `ProfilePage` | Active user dashboard (defaults to `Elena Rostova`), showing profile avatar, bio, home city, aggregate statistics (trips created, saved destinations), tabbed views for "My Itineraries" and "Saved Wishlist", and quick actions to create new trips. |
| `*` | `NotFoundPage` | Custom 404 "Off the Beaten Path" error page with a direct link to return to the homepage. |

## 4. Shared Components & UI Systems

All components adhere to clean separation of concerns and use CSS classes defined in the centralized stylesheet system:

- **`DestinationCard`**: Renders destination cover imagery, country label, continent tag, budget tier indicator, best season badge, and an interactive bookmark button that updates state optimistically.
- **`TripCard`**: Displays trip title, destination affiliation, author avatar and name, start/end dates, total stop count, estimated budget with currency symbol, and like count badge.
- **`LoadingSkeleton`**: Provides pulsating placeholder cards (`CardSkeleton`), grid layouts (`GridSkeleton`), and detailed page placeholders (`DetailSkeleton`) during asynchronous data fetches to minimize layout shifts.
- **`EmptyState`**: Standardized component for zero-result queries, empty wishlists, or empty trip lists with custom icons, descriptive messages, and call-to-action buttons.
- **`ConfirmModal`**: Accessible modal overlay for destructive operations (deleting a trip or deleting a comment), featuring danger action buttons and cancellation shortcuts.
- **`ErrorBanner`**: User-friendly notification banner displayed when an API request fails, offering clear feedback and optional retry callbacks.
- **`Navbar`**: Fixed editorial header containing the brand mark, navigation links (Destinations, Itineraries, Plan Trip, Profile), and a mobile drawer toggle with smooth transitions.
- **`Footer`**: Balanced site footer with brand overview, destination links, technical assignment attribution, and technology badges.

## 6. API Client & Express Proxy Integration

### The Centralized API Client (`src/services/api.js`)
All communication with the backend is routed through a single fetch wrapper that:
1. Prefixes endpoints with `/api`.
2. Sets `Content-Type: application/json`.
3. Injects the active user identity via the `x-user-id` header (default: ID `1`, `Elena Rostova`).
4. Serializes query parameter objects into valid URL search strings.
5. Standardizes error responses into custom `Error` instances containing HTTP status codes and validation details.

### How Requests Reach Express via Vite Proxy
In development, the frontend runs on port `5173` and the Express backend runs on port `5000`. The Vite development configuration (`vite.config.js`) proxies all `/api` requests:

```javascript
// vite.config.js
export default defineConfig({
  plugins: [react()],
  server: {
    port: 5173,
    proxy: {
      '/api': {
        target: 'http://localhost:5000',
        changeOrigin: true
      }
    }
  }
});
```

**Request Flow:**
```text
Browser Client (http://localhost:5173)
   │
   │ fetch('/api/destinations')
   ▼
Vite Dev Server (Port 5173)
   │
   │ Proxy forwards request to http://localhost:5000/api/destinations
   ▼
Express Backend API (Port 5000)
   │
   │ Returns JSON response
   ▼
Browser Client receives data seamlessly (No CORS complications)
```

## 7. Prerequisites & Getting Started

### Prerequisites
- **Node.js**: `v20.0.0` or higher (`v24.21.0` recommended)
- **npm**: `v10.0.0` or higher
- **Running Backend**: The Roamly Express backend must be running on `http://localhost:5000` for live data.

### Installation
From the repository root:
```bash
cd frontend
npm install
```

### Running the Development Server
```bash
npm run dev
```
The application will be available at **`http://localhost:5173`**.

### Building for Production
```bash
npm run build
```
Generates a minified, production-ready static bundle in `frontend/dist/`.

### Previewing the Production Build
```bash
npm run preview
```
Serves the contents of `frontend/dist/` locally for pre-deployment verification.

### Code Quality & Linting
```bash
npm run lint
```
Executes `oxlint` against all JSX and JS files with React Hooks and component export rules.

## 8. Configuration Assumptions & Troubleshooting

### Environment Assumptions
- **Backend Host & Port**: The development proxy assumes the backend is listening at `http://localhost:5000`. If you configure a custom port via `PORT` in `backend/.env`, update the `target` URL in `frontend/vite.config.js` accordingly.
- **Active User Session**: Roamly runs in lightweight demo mode without requiring third-party authentication credentials. User identity is managed by setting the active user ID (default `1`, Elena Rostova) via the `x-user-id` header in `src/services/api.js`.
- **Image Assets**: Destination cover photos and avatars use external Unsplash CDN URLs. An active internet connection is required for external images to render properly.

### Troubleshooting

| Issue | Root Cause | Solution |
| :--- | :--- | :--- |
| **"Unable to connect to the Roamly server"** | Backend API is not running or running on an unexpected port. | Open a separate terminal, navigate to `backend/`, and start the server with `npm run dev`. Ensure it is listening on port `5000`. |
| **Port 5173 is already in use** | Another local process is occupying port 5173. | Vite will automatically prompt or switch to port 5174. If needed, specify a custom port in `vite.config.js` or terminate the conflicting process. |
| **HTTP 403 Forbidden when editing or deleting** | Attempting to update or delete a trip or comment created by another author. | Only the author of a trip or comment may modify or delete it. Switch to the owner's user ID or edit resources created by the active user (`Elena Rostova`, User ID 1). |
| **Missing images or placeholders** | No internet connection or blocked CDN requests. | Check network connectivity to `images.unsplash.com`. The local asset `frontend/src/assets/hero.png` will still load offline. |
